## W2.1 — Filter-literal existence probe  (HIGH value; diagnostic accelerator)

**Failure it addresses:** the primary cause of the Macroeconomics blanking — a
control default value `"Americas & Caribbean"` that no row carries (the DM calc
emitted `"Americas and Caribbean"`), and Top-3 list filters `["2015"]` against a
`TIMESTAMP` column. W1.1 already turns this RED at verification (empty tiles); W2.1
catches the CAUSE earlier and names the exact literal + near-miss, which is what
saves the ~30 min of no-data hunting.

**Spec:** a new `scripts/probe-filter-literals.rb --workbook-id <id>
[--workbook-spec <spec>] --out filter-probe.json`:
1. From the live/loaded workbook spec, enumerate every (column, literal) filter
   condition: (a) control default `value`/`values` + the column each control
   `filters` targets (walk `filters[].{source.elementId, columnId}`); (b) every
   element `filters[]` of `kind:"list"` with literal `values`.
2. Resolve each `columnId` to the underlying column/formula and the element that
   owns the UNFILTERED domain (the feeder/base table — the `masterAll`-style twin,
   NOT the filtered `master`). Query its DISTINCT domain (Sigma element export of
   the unfiltered source, or a `SELECT DISTINCT` via the sigma query API).
3. For each literal, check membership in that domain. Miss → report with
   edit-distance near-misses (`"Americas & Caribbean"` ≈ `"Americas and Caribbean"`,
   distance 3) and the column.
4. **Degrade to a WARNING, never a hard stop, when the column can't be resolved**
   — W1.1's emptiness gate is the hard teeth; W2.1 is the pointer. This keeps
   corpus false-positive risk at zero.

**Anti-overfit note:** the near-miss heuristic (edit distance, `&`↔`and`,
case/space normalization) is generic string logic, not workbook-specific. The
date-part case (`["2015"]` vs timestamps) generalizes to "a list literal that
parses as a bare year/number against a temporal/numeric column" — grammar-level,
not fixture-level.

## W2.2 — Typed-literal calc lint  (HARD; .twb grammar + Sigma formula semantics)

**Failure it addresses:** the post-fix cause the field run never diagnosed —
converter calcs `If([Year] = "2014", [Teu Value])` where `Year` is NUMBER compile
clean and render NULL for every measure; same for a date-part filter emitted as a
string list against a `TIMESTAMP`.

**Spec:** a lint over the generated DM/workbook formulas (a new lint in
`scripts/lib/`, wired into the existing calc-lint path):
- Detect a comparison/equality between a column KNOWN numeric/temporal (from the
  landed warehouse schema or the Sigma column type) and a STRING literal. Tableau's
  `YEAR()`/`DATEPART` produce integers; a converter that renders `YEAR([Date]) =
  2015` as a string `"2015"` comparison is the bug class.
- Emit a hard lint finding + an auto-coercion suggestion (`Number([Year]) = 2014`
  or a real `DatePart`/`DateTrunc` predicate / a derived year column).
- Must consult the ACTUAL column type (landed schema or live `/columns`), not guess
  from the name — a string column literally named "Year" must NOT be coerced.

**Why Fable:** correctly distinguishing "numeric column compared to a string
literal that should be numeric" from legitimate string comparisons needs real
type-resolution + Sigma formula-grammar reasoning, and the auto-coercion must be
provably type-safe. A hasty version risks rewriting valid formulas (corpus
regressions). Derive strictly from the .twb calc grammar + the resolved column
type; zero fixture literals.

## W2.3 — Landed-schema ↔ formula type reconciliation preflight  (MEDIUM-HARD)

**Failure it addresses:** the 18-min 25→16→10→0 error-column loop — `land-extracts.py`
landed Year/Date as TEXT while generated formulas compared integers / DateTrunc'd.

**Spec:** after landing + before (or at) DM POST, diff the landed warehouse column
types against the types the generated formulas assume; auto-inject casts (or fix
the landing types) so the loop converges in one pass instead of five DM PUTs.
Requires reading the warehouse `INFORMATION_SCHEMA` (or the landed table describe)
and the formula type expectations. Overlaps W2.2's type-resolution machinery — do
them together.

## W2.4 — Converter duplicate-ID fix  (CROSS-REPO; needs the vendored converter)

**Failure it addresses:** ~25 min lost — the vendored converter
(`sigma-data-model-mcp`, PROVENANCE commit c33e5bd) emitted duplicate element/
control IDs into `dm-spec.json` twice, forcing hand-edits and setting up the later
brick. Task #25's dedupe covered the WORKBOOK spec only; the dm-spec dupes were
never covered.

**Two parts:**
1. **Upstream (needs the `sigma-data-model-mcp` repo — not in this checkout):** fix
   the id generator so it never emits duplicate element/control ids for a 2-extract
   workbook. This is the real fix.
2. **Orchestrator-side belt-and-suspenders (doable here):** a preflight in
   `post-and-readback.rb` (or a lib) that dedupes dm-spec element/control ids BEFORE
   the DM POST and warns, so the model never has to hand-edit even if the converter
   regresses. This part could be done in-repo now; item 1 needs the other repo.

## W1.7 — Per-tile blank detector in visual-similarity  (MEDIUM; superseded as primary)

**Failure it addresses:** gate 14 passed the dataless render 0.521 / ink 0.401 vs
the 0.40 floor because titles + headers + nine "No data" placeholders supplied
enough global ink. W1.1's per-element export check is now the PRIMARY, deterministic
catch, so this is defense-in-depth, not the teeth.

**Spec:** using the layout's tile bounding boxes (from `dashboard-layout.json` /
`layout-census.json`), compute per-tile interior edge-ink in `visual-similarity.py`;
require ≥ X% of CHART tiles to be non-blank (a "No data" placeholder is near-blank
interior). Emit a `per_tile_blank` array. Calibrate X against the corpus so healthy
sparse charts don't trip it — this calibration is why it's a careful pass, not a
quick one.

## W3.4 — Compaction-resistant run journal  (MEDIUM)

**Failure it addresses:** 4 compactions cost ~9 min AND one laundered the false
"export doesn't run queries" theory into a post-compaction "Key Technical Concept"
(fact), which every later gate decision inherited.

**Spec:** the orchestrator maintains a `run-journal.jsonl` of decisions, OPEN
hypotheses (recorded AS hypotheses, not facts), and UNRESOLVED contradictions. The
operating contract requires re-reading it after any compaction. A hypothesis
("maybe the export doesn't run queries") must never graduate to a fact without a
recorded probe result — ties into W1.5's probe requirement.
